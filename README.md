## 这是什么

背单词表最难受的不是「记不住」，是**记了没用**。

孤立的词条只给你「拼写 ↔ 中文」的映射，而考试考的是这个词在句子里的行为：它常跟哪个介词、阅读里被同义改写成什么、作文里能不能升级替换。这些在词表里全都没有。

所以这个项目换了条路：把 26 个单元、1837 个必考词**拆散再重组**，每 12–20 个词编成一篇考研题材的英文小故事，目标词自然地长在句子里。读故事的时候，词是在上下文里被记住的 —— 顺带记住它跟什么介词搭、在什么文体里出现。

每篇故事的目标词还各配一张**五维考点卡**：核心搭配 / 近义替换 / 词族延伸 / 易混辨析 / 加分句式。**故事负责记住，卡片负责会用。**

产出的不是一份词表，而是一套完整的自用工具：26 个可离线打开的单页应用 + 一个总目录页，覆盖「读 → 背 → 写 → 查 → 生词本」五条链路。所有内容、数据、前端代码都在这个仓库里 —— 可以直接拿去用，也可以照着管线做一套自己的。

## 五个功能：STORY

五条链路的英文名首字母，正好拼成本产品的主题词 **STORY**：

| | 英文名 | | 做什么 |
|---|---|---|---|
| **S** | Story | **读** | 按篇读故事，点加粗的目标词直接翻考点卡；译文折叠在文末，一键展开 |
| **T** | Test | **背** | 遮住释义翻卡自测；顶部词轨一格一词，颜色即掌握度，可点可拖 |
| **O** | Output | **写** | 把全部加分句式抽成可搜索的句子库，搭配短语做成可点读的 chip |
| **R** | Reference | **查** | 全量速查表，支持英文 / 中文 / 词根三种搜法 |
| **Y** | Yours | **本** | 生词本。自己收词、自己补发音、攒够一批自测 —— 这本是你的 |

页面里目前以「读 / 背 / 写 / 查 / 本」单字呈现，英文名是这套功能的正式命名。选 STORY 不是硬凑：**读**本来就是主线，其余四个都是从故事里长出来的分叉 —— 先读，才知道哪些词没记住；记住了，才谈得上写和查。

## 功能特性

### 读 ・ 背 ・ 写 ・ 查 ・ 本

- **读**：选篇 → 读英文故事 → 点加粗词看考点卡。中文译文整篇折叠在文末，展开 / 收起的状态跨单元记住
- **背**：顶部是一条**词轨** —— 一格一个词，颜色就是掌握度，可点、可拖、可用方向键跳转，亮色占比本身就是进度。卡片可翻面，背面是完整考点
- **写**：作文素材库，按加分句式出处检索，点一下就能听
- **查**：全量速查表，英文、中文、词根都能搜；点任意一行展开完整考点
- **本**：背词时点「没记住」自动收录，读故事遇到生词也能收进来；生词可以自己补发音，攒够了一批直接开测

### 朗读（离线预生成的神经网络语音）

- 三个英文音色（女声亲切 / 男声明亮 / 男声沉稳）+ 一个中文音色，选择会记住
- 段落整段朗读，**逐句高亮跟读**：句子跟着语音亮起来并自动滚进视野，也可以单独点某一句精读
- 三档可调：**关** / **手动**（默认，背词时自动读词，其余点 🔊 才发声）/ **自动**（翻面时连释义一起读）
- 背词模式进卡自动读词，但**读词时不读中文**（防泄底）；语速支持慢速跟读 / 正常 / 快速过词

### 页面设置（吸顶条右侧 ⚙️）

- **展示视角排版**：电脑宽屏 / 手机单列，两种排版一键切换、即时生效 —— 在电脑上就能预览手机版观感
- **语音朗读控制**：模式（关 / 手动 / 自动）、语速（0.75× / 1× / 1.15×）、英音音色与**试听**，全部集中在一个面板里
- 吸顶条右侧常驻 **`Unit NN ▾` 单元徽章**，点开是 26 格选关矩阵，换单元不必回目录页

### 其他

- 桌面 + 手机响应式，通勤路上也能刷
- 进度、掌握度、自测范围、朗读偏好全部存本地，换设备不用登录
- 零依赖、零后端：单个 HTML 双击就能跑（音频需要走 `file://` 或本地服务器）

## 快速开始

**前置条件**：Python 3.9 或更高（开发环境为 3.13）。只用于起本地服务器和生成音频 —— **浏览页面本身不需要 Python**。

```bash
git clone <你的仓库地址>
cd WowStory
```

然后起本地服务器：

- **Windows**：双击 `单词故事本/serve.cmd`
- **macOS / Linux**：`python3 单词故事本/serve.py`

浏览器会自动打开，默认 `http://127.0.0.1:8899`（端口被占用会自动 +1）。

```bash
python 单词故事本/serve.py --port 9000      # 换起始端口
python 单词故事本/serve.py --lan            # 局域网可访问，手机 / 平板能开
python 单词故事本/serve.py --no-browser     # 不起浏览器
```

> ⚠️ 页面里的音频走相对路径。请**双击 HTML 用浏览器打开**，或用上面的服务器。用「内嵌预览面板」之类的宿主打开时相对路径解析不到磁盘，会提示「音频没找到」—— 这不是文件坏了。

### 补朗读音频

**仓库不含音频**（618 MB / 31,869 个文件，不适合进版本控制）。三种补齐方式：

```bash
# 1) 全量生成（默认 1–26 单元）
pip install edge-tts
python scripts/gen_all_audio.py

# 2) 只补某个单元
python scripts/gen_unit_audio.py 1

# 3) 在页面里补（生词本专用）
#    服务器在跑时：一键补生词发音
#    机器上还没有 edge-tts：页面会先「一键准备朗读引擎」
```

第 3 种靠 `serve.py` 暴露的本机小 API 完成（`/api/setup` 建项目内 venv 并装 edge-tts，`/api/vocab/audio` 跑生成任务，页面轮询进度）。服务器不可用时会自动退回「导出 `vocab.json` → 本地跑脚本」的老路，两条路都留着出口。

音频生成可中断续跑：已存在的文件会跳过。

### 改完数据后重编译

```bash
python scripts/build_unit_html.py all      # 重编译 26 个页面
python 单词故事本/_sync_app.py             # 同步运行时镜像
```

## 技术实现

### 数据与呈现分离 —— 这是能扩展到 26 个单元的前提

词是原子，故事引用词。`UnitNN.json` 是**唯一真源**，页面和 Markdown 都是编译产物：

```jsonc
{
  "stories": [{ "id": "s1", "en": "The Safeguard", "zh": "守护", "theme": "社会",
                "ps": [{ "en": "…[[safeguard]]…", "zh": "…" }] }],
  "words":   [{ "w": "safeguard", "ipa": "ˈseɪfɡɑːrd", "pos": "v.", "s": "s1", "zh": "守护",
                "exam": "保护；捍卫", "c": ["safeguard against"], "syn": ["protect"],
                "fam": ["safeguarding"], "dif": "…", "pat": "…", "patZh": "…" }]
}
```

正文里的目标词用 `[[word]]` 标记，变形写 `[[surface|base]]`。词表、速查表、覆盖率这些**派生信息一律不写进 JSON**（否则就有了第二处真源），全部由渲染层算 —— 页面里现在写着「Unit 1 · 4 篇 · 53 词」，那个数字是算出来的，不是填进去的。

### 校验器当裁判，不靠肉眼

文本一长，「正文标了词、忘了建卡片」必犯。`validate_unit.py` 做确定性检查：词集与词表对齐、标记闭合、字段齐全、故事覆盖率 100%、篇数符合「由词数反推」的区间……输出 13 类 ERROR，**必须 ERROR 0 才算通过**。

这一层的意义是：生成端可以换任何模型、任何提示词，**验收标准只有一份**。

### 朗读：离线预生成 + 句级时间轴

不用 Web Speech API —— 音质取决于系统语音包，各浏览器还不一致。改成用 `edge-tts` 离线合成 mp3，浏览器只负责播放，任何浏览器听感一致。

段落是一条完整音频，同时提取每句的起始时间戳内联进页面（`var PT`），播放时按时间轴推进逐句高亮。**断句正则前后端严格同一套**，否则句数和时间轴会对不上。

### 生词本与书里词表：命名空间隔离

书里的词用单词本身当索引；如果生词本也这么干，收了一个同名词就会互相串味。所以生词本用**自生成的 id 作身份键**，两条链完全平行 —— 掌握度、释义、音频路径各算各的，音频也落在独立目录。

### 本地服务器：给页面一个真 URL + 一点本机能力

页面里的音频全是相对路径，只有以真 URL 打开才找得到文件，所以起了个本地服务器（顺带自动开浏览器）。它还额外提供几个只服务本机页面的接口，让「补生词发音」「装朗读引擎」能在页面上点一下就完成。

**写接口默认只在绑 `127.0.0.1` 时开放**。加 `--lan` 之后同 WiFi 下别的设备也能访问，那里默认关掉写接口 —— 否则任何同网设备都能让你机器上的 Python 去调外部服务并往你硬盘写文件。要用就显式加 `--allow-write`。

## 自己造一本

想换一套词表（四六级、雅思、日语 N1……）只需要准备一份 CSV，字段：

```csv
单元,单词名,单词中文翻译,常考含义
Unit 1,radiate,v．发出，发射出…,辐射；发散
```

然后按 [`skill/word-storybook-generation/SKILL.md`](./skill/word-storybook-generation/SKILL.md) 的规范产出 `UnitNN.json`（分组方案、故事、卡片都可以交给任意 LLM），跑校验器到 ERROR 0，再走 `scripts/` 里的音频与编译流程。

`skill/word-storybook-generation/` 里包含：

- `SKILL.md` —— 完整的信息清单（哪些字段来自词表、哪些由模型生成、哪些由渲染层派生）与写作规则
- `validate_unit.py` —— 确定性校验器，13 类 ERROR，产出必须 ERROR 0 才算过
- `inspect_progress.py` —— 分批写作期的增量自检（列出「正文标了但还没建卡片」的词）
- `build_md.py` —— 由 JSON 派生可读版 Markdown
- `reference/unit01.example.json` —— 已验证 ERROR 0 的标准样例

上游还有一份配套 skill `csv-data-quality-audit`（不在本仓库内），用于入库前的词表质量审查：OCR 错字、末尾截断、重复词。

## 已知限制与路线图

- [ ] 部分单元的「故事义」字段还残留双义写法（写成了简版常考义），正在逐单元收成单义

- [ ] 音频未随仓库分发，首次使用需要自己生成（要联网调 edge-tts，耗时取决于网络；已生成的会跳过，可中断续跑）
- [ ] 目录页的篇数徽章是写死的，加单元时需要手动同步
- [ ] 暂不支持导出 Anki / 单词表
