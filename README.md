## 这是什么

考研单词表按字母或词根排，背的时候是一串没有上下文的孤立词条 —— 记住了拼写，记不住怎么用。

这个项目把 26 个单元、1837 个必考词**拆散再重组**：每 12–20 个词编成一篇考研英语一 / 英语二题材的英文小故事，目标词自然地长在句子里。读故事的同时把词记住，并且**顺手记住它在什么语境、跟什么介词搭**。

产出的不是一份词表，而是一个完整的自用工具：26 个可离线打开的单页应用，覆盖「读 → 背 → 写 → 查 → 生词本」五条链路。所有内容、数据、前端代码都在这个仓库里，可以直接拿去用，也可以照着管线做一套自己的。

## 为什么要做成故事

背单词最难受的不是"记不住"，是**记了没用**。孤立的词条只给你「拼写 ↔ 中文」的映射，而考试考的是这个词在句子里的行为：

- 它常跟哪个介词（`cater **to**` / `charge sb. **with**`）
- 阅读里它被同义改写成什么（`abolish` → `do away with`）
- 作文里能不能升级替换（`important` → `of vital importance`）

这些信息在词表里全都没有。所以每篇故事的目标词都配一张**五维考点卡**：核心搭配 / 近义替换 / 词族延伸 / 易混辨析 / 加分句式。故事负责「记住」，卡片负责「会用」。

另一个考量是**阅读本身**：故事有情节，读下去是自然的，而背词表永远需要意志力。121 篇故事里，篇名都是该篇的一个目标词，读完一篇等于收集了一个词。

## 功能特性

**五种模式，一条完整链路**

- **读**：按篇读故事，加粗的目标词可直接点开考点卡；中文译文整篇折叠在文末，一键展开 / 收起（默认展开，开关跨单元记住）
- **背**：遮住释义翻卡自测，顶部是一条**词轨** —— 一格一个词，颜色就是掌握度，可点、可拖、可用方向键跳转，亮色占比本身就是进度
- **写**：把 1837 条加分句式汇总成可搜索的句子库，搭配短语做成可点击朗读的 chip
- **查**：全量速查表，支持英文 / 中文 / 词根搜索
- **本**：生词本。背词时点「没记住」自动收录，读故事遇到生词也可以收进来，攒够了一批可以自测

**朗读（离线预生成神经网络语音）**

- 三个英文音色可选（女声亲切 / 男声明亮 / 男声沉稳）+ 中文音色，选择会记住
- 段落整段朗读，**逐句高亮跟读**：句子跟着语音亮起来并自动滚进视野，也可以单独点某一句精读
- 背词模式进卡自动读词，但**读词时不读中文**（防泄底）；三档可调：关 / 手动 / 自动（翻面时连释义一起读）

**其他**

- 桌面 + 手机响应式，手机上下班路上可以刷
- 进度、掌握度、自测范围、阅读偏好全部存本地，换设备不需要登录
- 零依赖、零后端：单个 HTML 文件双击就能跑（音频需要走 `file://` 或本地服务器）

## 快速开始

**前置条件**：Python 3.9 或更高（开发环境为 3.13）。仅用于起本地服务器和生成音频，**浏览页面本身不需要 Python**。

```bash
git clone <你的仓库地址>
cd 单词故事本
python serve.py
```

浏览器会自动打开，默认 `http://127.0.0.1:8899`。

- **Windows**：直接双击 `单词故事本/serve.cmd` 即可
- **手机 / 平板**（同一局域网）：`serve.cmd --lan`，然后用打印出来的地址访问
- **换端口**：`python serve.py --port 9000`

> ⚠️ 页面里的音频走相对路径。请**双击 HTML 用浏览器打开**，或用上面的 `serve.py`。用「内嵌预览面板」之类的宿主打开会拿不到音频，会提示「音频没找到」—— 这不是文件坏了。

**仓库不含音频**（618 MB / 31,869 个文件，不适合进版本控制）。需要朗读时自行生成：

```bash
pip install edge-tts
python scripts/gen_all_audio.py 1 26      # 生成音频 + 句级时间轴
python scripts/build_unit_html.py all     # 重编译 26 个页面
python 单词故事本/_sync_app.py            # 同步运行时镜像
```

## 技术实现

**数据与呈现分离** —— 这是能扩展到 26 个单元的前提

词是原子，故事引用词。`UnitNN.json` 是唯一真源，页面和 Markdown 都是编译产物：

```jsonc
{
  "stories": [{ "id": "s1", "en": "The Safeguard", "zh": "守护", "theme": "社会", "ps": [{ "en": "…[[safeguard]]…", "zh": "…" }] }],
  "words":   [{ "w": "safeguard", "ipa": "ˈseɪfɡɑːrd", "pos": "v.", "s": "s1", "zh": "守护",
                "exam": "保护；捍卫", "c": ["safeguard against"], "syn": ["protect"], "fam": ["safeguarding"],
                "dif": "…", "pat": "…", "patZh": "…" }]
}
```

正文里的目标词用 `[[word]]` 标记，变形写 `[[surface|base]]`。词表、速查表、覆盖率这些**派生信息不写进 JSON**（否则就有第二处真源），全部由渲染层算。

**校验器当裁判，不靠肉眼**

文本一长「漏建卡片」必犯。`validate_unit.py` 做确定性检查：词集与词表对齐、标记闭合、字段齐全、故事覆盖率 100%、篇数符合「由词数反推」的区间……输出 13 类 ERROR，**必须 ERROR 0 才算通过**。生成端可以换任何模型，校验器是唯一的验收标准。

**朗读：离线预生成 + 句级时间轴**

不用 Web Speech API（音质取决于系统语音包，且各浏览器不一致），改成用 `edge-tts` 离线把内容合成 mp3，浏览器只负责播放 —— 任何浏览器听感一致。

段落是一条完整音频，同时提取每句的起始时间戳内联进页面（`var PT`），播放时按时间轴推进逐句高亮。断句正则前后端严格同一套，否则句数和时间轴会对不上。

**生词本与书里词表命名空间隔离**

书里的词用单词本身当索引，生词本如果也出现同一个词会互相串味。所以生词本用**自生成的 id 作身份键**，两条链完全平行 —— 掌握度、释义、音频路径各算各的。

## 自己造一本

想换一套词表（四六级、雅思、日语 N1……）只需要准备一份 CSV，字段：

```csv
单元,单词名,单词中文翻译,常考含义
Unit 1,radiate,v．发出，发射出…,辐射；发散
```

然后按 [`skill/word-storybook-generation/SKILL.md`](./skill/word-storybook-generation/SKILL.md) 的规范生成 `UnitNN.json`（分组方案、故事、卡片都可以交给任意 LLM），跑校验器到 ERROR 0，再走 `scripts/` 里的音频与编译流程。

`skill/word-storybook-generation/` 里包含：

- `SKILL.md` —— 完整的信息清单（哪些字段来自词表、哪些由模型生成、哪些由渲染层派生）与生成规则
- `validate_unit.py` —— 确定性校验器，13 类 ERROR，产出必须 ERROR 0 才算过
- `inspect_progress.py` —— 分批写作期的增量自检（列出「正文标了但还没建卡片」的词）
- `build_md.py` —— 由 JSON 派生可读版 Markdown
- `reference/unit01.example.json` —— 已验证 ERROR 0 的标准样例

上游还有一份配套 skill `csv-data-quality-audit`（不在本仓库内），用于入库前的词表质量审查：OCR 错字、末尾截断、重复词。

## 已知限制与路线图

- [ ] 部分单元的「故事义」字段还残留双义写法（写成了简版常考义），正在逐单元收成单义
- [ ] 少数段落只有一句话，读起来略单薄
- [ ] 音频未随仓库分发，首次使用需要自己生成（要联网调 edge-tts，耗时取决于网络；已生成的会自动跳过，可中断续跑）
- [ ] 目录页的篇数徽章是写死的，加单元时需要手动同步
- [ ] 暂不支持导出 Anki / 单词表
